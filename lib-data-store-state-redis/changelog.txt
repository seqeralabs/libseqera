# lib-data-store-state-redis changelog

1.2.0 - 3 Aug 2026
- Add VersionAware interface: a value carries its own optimistic-concurrency version -
  version() accessor plus withVersion(long) copy method (#107)
- Add VersionedStateStore, a state store for VersionAware value types offering a
  versioned compare-and-swap write replaceIf(key, value[, ttl]): the write witness is
  the value's own version - the swap lands only when the stored version still equals
  it; AbstractStateStore keeps its pre-existing contract unchanged (#107)
- Versions are unique time-sorted identifiers (TSID) stamped by the store on every
  write path, put() included, so any write invalidates every outstanding witness -
  no put-is-creation-only invariant and no ABA across a remove-and-recreate
- The swap is a single atomic server-side operation (one round-trip): the store frames
  every versioned write with a leading {"@v":N} JSON property and the provider compares
  the stored version by peeking that frame (GETRANGE) - no payload parsing, no expected
  value on the wire, no re-serialization, cost independent of the value size
  (reflection-dependent property order broke the previous byte-equality compare in
  multi-replica deployments)
- Versioned values must serialize to a JSON object; the frame is transparent to the
  encoding strategy - stripped symmetrically on read, with its version injected into
  the decoded value via withVersion - so the frame is the single source of truth for
  the version, the value type need not serialize its version field, and the decoder
  always receives exactly the payload the encoder produced
- Reads are resilient to foreign data that merely resembles a frame: version digits
  that overflow a long - which no store-written frame can carry - fall back to
  decoding the stored form as-is at version 0, never a read failure; a plain
  AbstractStateStore never frames nor strips, so a genuine @v property of a
  non-versioned value is always preserved
- Entries written before versioning carry no frame, count as version 0, and are adopted
  transparently by their first successful replace
- replaceIf renews the entry time-to-live like every other write path: without an
  explicit ttl it resets to the store default duration, and the request-id mapping
  always shares the entry's ttl, so the findByRequestId index can never expire out of
  step with its entry; no time-to-live-preserving variant exists (and the Redis 6
  KEEPTTL requirement is gone with it)
- The compare-and-swap matches the frame digits literally against the canonical decimal
  form of the expected version - the only form a store-written frame can carry - in both
  providers, with no version parsing anywhere in the CAS path: foreign data whose head
  merely resembles a frame never matches and is left untouched, while reads degrade to
  version 0 with a warning when the digits do not fit a long, never a read failure
- The raw stored-form compare-and-swap added in 1.1.0 is removed and 1.1.0 is revoked
  (see below): the provider-level CAS is re-signed to the versioned form (key,
  expectedVersion, value) and moves to the new standalone VersionProvider capability
  interface, implemented by both providers alongside StateProvider, which keeps its
  pre-existing contract; no byte-level CAS remains anywhere in the API

1.1.0 - 1 Aug 2026 [REVOKED]
- REVOKED: the replaceIf added by this release compares a re-serialization of the
  expected value byte-wise, which silently requires the encoding strategy to be
  deterministic across JVMs - reflection-dependent property order breaks it in
  multi-replica deployments, making the CAS refuse persistently. The API was
  withdrawn in 1.2.0 before any consumer shipped on it; do not use this version
- Add replaceIf compare-and-swap write to StateStore, StateProvider and AbstractStateStore (#104)
- Atomic via a Lua script in RedisStateProvider (requires Redis 6.0+ for SET KEEPTTL);
  via ConcurrentHashMap.replace in LocalStateProvider
- Two variants: replaceIf(key, expected, value) preserves the entry's remaining TTL;
  replaceIf(key, expected, value, ttl) resets the TTL to the given duration
- Missing key or mismatching current value returns false; comparison is on the serialized form
- Rewrite the README against the actual API: it documented delete/incr/exists/keys methods
  that never existed, and omitted putIfAbsentAndCount and findByRequestId

1.0.0 - 4 Nov 2024
- Initial release of lib-data-store-state-redis extracted from Wave project
- Refactor package from io.seqera.wave.store.state to io.seqera.data.store.state
- Implement StateStore interface for distributed state management
- Add AbstractStateStore base class with serialization support
- Add LocalStateProvider for in-memory state storage with Lua script support
- Add RedisStateProvider implementation using Jedis client
- Support atomic counter operations with CountParams and CountResult
- Support RequestIdAware interface for request tracking
- Add StateEntry data class for state management
- Use RedisActivator marker interface for conditional bean loading
- Use centralized TestRedisActivation from lib-fixtures-redis
- Include comprehensive test suite with Redis testcontainers
